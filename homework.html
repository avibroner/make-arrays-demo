מערכים וקולקשנים

בתרגיל הזה תעבדו על רשימה של 50 משימות שמגיעה מכתובת אינטרנט, ותתרגלו את הפונקציות והמודולים שלמדנו בשיעור. ליד רוב התרגילים מופיעה התוצאה הנכונה, כדי שתוכלו לבדוק את עצמכן.

שלב 0 מביאות את הנתונים

  1. צרו תרחיש חדש והוסיפו את המודול HTTP > Make a request.
  2. בשדה URL הדביקו את הכתובת: https://avibroner.github.io/make-arrays-demo/tasks.json
  3. Method: GET. סמנו Parse response = Yes. אין צורך בהרשאה או ב-headers.
  4. לחצו Run once ופתחו את הבועה של המודול.

בפלט תמצאו את Data, ובתוכו את המערך tasks. כל פריט במערך הוא קולקשן שנראה כך:

{
  "id": 1,
  "subject": "לתאם שיחת הדגמה",
  "description": "הדגמה של חצי שעה על המערכת ללקוח מתעניין.",
  "details": {
    "status": "הושלם",
    "priority": "גבוהה",
    "type": "משימה"
  },
  "due_date": "2026-11-12"
}

שימו לב: details הוא קולקשן שנמצא בתוך קולקשן. המערך ממוין לפי due_date, מהמוקדם למאוחר.

לכל התרגילים בחלקים א ו-ב הוסיפו אחרי ה-HTTP מודול Tools > Set variable וכתבו בו את הנוסחה. כך רואים את התוצאה בבועה של המודול.

חלק א מערכים

1 כמה משימות יש?

החזירו את מספר הפריטים במערך tasks.

תוצאה: 50

2 הראשונה והאחרונה

החזירו את הנושא (subject) של המשימה הראשונה במערך, ובמשתנה נוסף את הנושא של האחרונה.

ראשונה: לתאם שיחת הדגמה אחרונה: לבדוק נתוני שימוש של הלקוח

3 המשימה העשירית

החזירו את הנושא של הפריט העשירי במערך, בלי להשתמש ב-Iterator.

תוצאה: לעדכן את צוות המכירות על שינוי במחירון

4 רשימת כל הנושאים

צרו מערך חדש שמכיל רק את הנושאים של כל המשימות. אחר כך הפכו אותו לטקסט אחד, שבו הנושאים מופרדים בפסיק ורווח.

הטקסט מתחיל ב: לתאם שיחת הדגמה, לשלוח הצעת מחיר לשירות נוסף, לתאם פגישת סיכום שנה

חלק ב קולקשנים וסינון

5 שדה בתוך קולקשן מקונן

מהי העדיפות (priority) של המשימה השלישית במערך? זכרו שהעדיפות נמצאת בתוך details.

תוצאה: רגילה

6 רק הצעות מחיר

החזירו מערך של הנושאים של המשימות שהסוג שלהן (details.type) הוא "הצעת מחיר".

4 נושאים: לשלוח הצעת מחיר לשירות נוסף, להכין הצעה למכרז, לשלוח הצעת מחיר מעודכנת, לחדש הסכם שירות

7 כמה משימות פתוחות?

חשבו בנוסחה אחת כמה משימות נמצאות בסטטוס "פתוח".

תוצאה: 35

חלק ג Iterator ו-Array aggregator

8 משימות פתוחות בעדיפות גבוהה

הפעם יש שני תנאים, ולכן map כבר לא מספיק. בנו את הזרימה הבאה:

  1. Iterator שמפרק את המערך tasks לבאנדלים.
  2. פילטר שמעביר רק משימות שהסטטוס שלהן "פתוח" וגם העדיפות שלהן "גבוהה".
  3. Array aggregator שבונה מערך חדש, ובו רק השדות id ו-subject.
במערך החדש 10 פריטים. ה-id שלהם: 16, 22, 24, 27, 30, 34, 36, 39, 42, 50

שאלה למחשבה: כמה פעמים רץ ה-Iterator, כמה באנדלים עברו את הפילטר, וכמה באנדלים יצאו מה-Array aggregator? כתבו את שלושת המספרים והסבירו במשפט אחד למה הם שונים.

שתי השורות הראשונות (הסדר ביניהן יכול להתחלף, כי התאריך שלהן זהה): לבדוק נתוני שימוש של הלקוח, לתאם פגישת צוות שבועית
